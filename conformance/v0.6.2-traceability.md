# SCQ v0.6.2 — Specification-to-Implementation Traceability Matrix

Status: **candidate-supporting document for a DRAFT specification.** v0.6.2 is not approved,
published, or released; v0.6.1 remains the current specification. This matrix maps every new
or modified normative MUST/MUST NOT in `spec/scq-v0.6.2-spec.md` (rule IDs per its
Appendix B) to the implementation and the tests that establish the obligation.

**Reading rules (binding on this matrix):**

- A rule is marked IMPLEMENTED only where a test *establishes the obligation* — a similar
  function or a nearby test is not evidence.
- Evidence levels: **simulated** (in-repo simulators, mocked transports, unit/integration
  tests), **live** (exercised against a real provider API), **documentation-backed**
  (provider documentation or recorded live-session evidence), **unverified** (no evidence).
  A passing integration simulation is not independent provider adoption and not production
  conformance.
- Tests 37–42 (PR-11 pilot preflight/rehearsal) are mapped separately in §3 as
  **pilot-readiness evidence**. They are not normative protocol conformance tests and are
  never cited as establishing a §6 rule.
- Known shortfalls are stated in the Assessment column and carried in
  `research/v0.6.2-release-gaps.md`; nothing here quietly upgrades them.

  adding duplicates would not have strengthened the evidence. The two spots where
