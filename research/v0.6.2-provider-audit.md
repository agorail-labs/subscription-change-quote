# SCQ v0.6.2 — Provider Audit (all five adapters)

Status: **supporting document for SCQ v0.6.2, published as an experimental specification.**
v0.6.2 was ratified by the maintainer (PR #21, Oct 31, 2026) and is published as the project's
current experimental specification by the publication change carrying this header; the
`spec-v0.6.2` tag and GitHub Release are created by the maintainer at activation. v0.6.1 is
the previous specification. The audit findings below are the record as audited and are not
rewritten.

**Evidence discipline (read first).** Four of the five adapters are *simulators* —
in-repo models of provider behaviour — and the fifth (Chargebee-live) has only ever run
against mocked transports in tests, plus a historical **read-only** live session for
estimates/reads. Therefore:

- The three non-Chargebee adapters (Stripe sim, Paddle sim, Zuora sim) and the Chargebee
  simulator carry **simulation evidence only**. Nothing in this audit is live validation
  of Stripe, Paddle, or Zuora, and no claim is made about those providers' real APIs
  beyond what their public documentation describes.
- The historical Chargebee live reads/estimates (Oct 2026, L-GET/L-QUOTE LIVE_PASS)
  establish that the read and estimate paths behave as documented against a real test
  site. They do **not** establish live commit correctness: no live mutation has ever
  been executed or authorized.
- "Provider-documented" below means the capability is described in the provider's public
  documentation (or the repo's recorded research). "Exercised" means this repository's
  code actually calls/models it and a test pins the behaviour. Where the two differ, the
  difference is stated.
- No claim of production readiness, provider endorsement, provider adoption, or official
  protocol status is made anywhere in this audit.

Coverage vocabulary follows the spec: EXACT (provider-computable target state),
REVALIDATE (provider cannot promise the value; re-check at commit), and determinacy
DETERMINED / NOT_APPLICABLE / UNKNOWN per financial dimension.

## 1. Stripe simulator (`reference/src/adapters/stripe-adapter.ts`)

| Financial determinacy | `immediate` from the preview's incurred figure (PR #10 correction; `amount_due` never mapped — BC-3). Preview withholding the incurred figure ⇒ `immediate` UNKNOWN. Recurring DETERMINED from the preview's recurring figure. Cancellation immediate is licensed NOT_APPLICABLE (field absent, citation carried). |
| Quote-side provenance | `pre_mutation_estimate` lineage on quote/revalidation figures. |

Verification-read failure after landing ⇒ COMMITTED_UNVERIFIED recording the mutation response's figures as labeled **candidates** (UNKNOWN determinacy, `committedSource: "unestablished"` — §3.10 carve-out, V62-EVD-08), present for later verification, establishing nothing (test17.10). |
| State verification | Adapter-owned establishment over the persisted subscription (item set + scheduled-cancellation state); does not consume the shared §6.12 hook (see gap G-08). EXACT coverage for financials: CANCEL [IMMEDIATE, TERM_END], other actions [IMMEDIATE]. |
| EXACT eligibility | Yes within the coverage above; eligibility computed from the adapter's coverage table, not caller-asserted. |
| REVALIDATE enforcement | Shared BC-1 gate (engine) applies; adapter refuses UNKNOWN pre-mutation (test35.33). |
| Idempotency + replay | In-memory store semantics; receipts replay identically; durable-path behaviour is store-level, not adapter-specific. |

## 5. Chargebee-live adapter, experimental (`reference/src/live/chargebee-scq-adapter.ts`)

| Dimension | Audit |
|---|---|
| Actions + timing | IMMEDIATE only; actions CHANGE_PLAN, CHANGE_QUANTITY, ADD_ITEM, REMOVE_ITEM (CANCEL excluded — recurring dimension stays UNKNOWN, failing the envelope honestly). TERM_END/NEXT_CYCLE unsupported. `termEffect` UNKNOWN by construction. |
| Financial determinacy | From the real estimate endpoint's shape: `immediate` UNKNOWN (incurred not exposed); recurring DETERMINED where the estimate determines it. A quote from this adapter therefore **cannot pass an envelope gate on `immediate`** — by design, not by defect (gap G-06 records the open provider question). |
| Quote-side provenance | `pre_mutation_estimate`. |
| Committed actuals | Post-commit reads of the subscription/invoice state bound to the mutation; landed-but-unverifiable ⇒ typed COMMITTED_UNVERIFIED receipt (Defect 3 closure, PR #16). Where the response was received but the independent re-read fails, the receipt records the response's figures as labeled **candidates** (UNKNOWN, `unestablished` — §3.10 carve-out, V62-EVD-08) so a later verification compares against the originals (test26.17). Other unverified branches (broken attribution, incomplete re-read data) leave the unestablished recurring dimension's figure absent — candidates are permitted, never required. |
| State verification | Consumes the shared §6.12 hook at FULL_ITEM_SET (PR #18 wiring); VERIFIED state never establishes figures (V62-SV-08). A VERIFIED verdict is target-state conformance only — it is NOT preservation evidence for out-of-scope state (§6.12/§6.17). |
| Authorization preservation (PR #24) | **Standing blocker.** Sole update dispatch is `update_for_items` with `replace_items_list=true`; capability FULL_REPLACEMENT_ONLY is declared by a module-private constant behind a getter (runtime assignment/`defineProperty` cannot falsify it — test47.13–47.15). OPERATION-authorized update commits refuse pre-dispatch with `AUTHORIZATION_PRESERVATION_UNENFORCEABLE` (CONFIRMED_NON_EXECUTION semantics, zero attempts — test47). TARGET_REPLACEMENT refused at creation. CANCEL refused at creation (never dispatched). No documented conditional write/CAS closes the race (gap G-17). |
| Identity binding (PR #26) | Creation and commit-phase reads naming a foreign subscription refuse pre-dispatch (test49.1/49.2); post-dispatch foreign data is never consumed as evidence (test49.3). Unit context: currency threaded; cadence deliberately NOT threaded on this adapter (construction placeholder, disclosed — comparability for cadence rests on the effects' own statements). |
| Runtime validation (PR #25) | Shared validator is the first statement of creation; stored record re-validated at commit before any durable attempt (test48.16). |
| Receipt evidence (PR #27) | Receipts recorded through the store carry the append-only evidence trail + derived view; candidate recording on the no-reread branch is this adapter's test26.17 shape; later establishment follows §6.15/test50, never candidate matching. |
| Outcome taxonomy | Full §3.12 implementation: L1 lost-response-with-matching-state stays INDETERMINATE with re-dispatch refused; L2 CONFIRMED_NON_EXECUTION only for demonstrably pre-effect failures; L3 request-refusal narrowing = HTTP 400 + allowlisted code only (test26, test13 HTTP-layer pins). |
| EXACT eligibility | None. REVALIDATE family; BC-1 gate applies and will refuse UNKNOWN `immediate` quotes under envelope — expected behaviour until/unless the provider exposes an incurred figure. |
| REVALIDATE enforcement | Shared engine gate + store-level establishment branding. |
| Idempotency + replay | Durable store + write-ahead coordinator required for commit paths (mismatched wiring refused); provider idempotency key sent on the mutation request (test13); durable replay/restart suites test27–30; pilot rehearsal test38. |
| Partial execution / concurrency | Same-subscription exclusion enforced by the durable ledger; DISPATCHING recovery after 30 s grace ⇒ INDETERMINATE. Cross-process safety rests on the single-writer model (§6.16) — a deployment constraint, not a provider property. |
| Unsupported / unverified | **Everything live beyond reads/estimates is unverified.** No live commit has ever run. The `SCQ_LIVE_COMMIT_ENABLED` gate exists and stays unset (test35.32 pins that the gate blocks real mutation paths). Error-classification allowlist has never met the real error surface (G-10). |

Evidence level: **simulated** (mocked transports) for all commit behaviour;
**live** only for the historical read/estimate session; **documentation-backed** for API
shapes and the error-code research in test13's fixtures.

## 5b. Cross-cutting reconciliation behaviours (PRs #25–#27, all adapters)

- **Runtime validation (PR #25):** the shared validator (`validateProposalRuntime` /
  `validateStoredQuoteRuntime`) is the first statement of every adapter's
  `createChangeQuote` and runs over the stored record at every commit (test48). All
  five adapters refuse the same malformed classes with the same codes.
- **Identity binding (PR #26):** the shared hook's `state:subscriptionIdentity` check
  binds every adapter's establishment through the store (`expectedSubscriptionRef`
  threaded by `establishVerification`); adapter-level asserted-ref patterns (Stripe,
  Paddle) are bound the same way (test49.3/49.5, test50.7).
- **Unit comparability (PR #26):** one shared assessment in the engine serves every
  adapter's gate, reconciliation, and store recomputation (test49). Unit context is
  threaded through Zuora and Chargebee-sim establishments and the live adapter's
  revalidation/establishment (currency; the live adapter's cadence is a disclosed
  construction placeholder — see §5).
- **Receipt evidence (PR #27):** the evidence-trail / derived-view model is
  store-level, so it applies identically to receipts from all five adapters (test50).

## 6. Cross-provider summary

| Adapter | Evidence | EXACT financials | Committed actuals bound to mutation | §6.12 hook consumed | Live commit |
|---|---|---|---|---|---|
| Stripe sim | simulated | CANCEL both timings; others IMMEDIATE | Yes (invoice) | No (adapter-owned) | n/a |
| Paddle sim | simulated | CANCEL | Yes (transaction id) | No (adapter-owned, P3) | n/a |
| Zuora sim | simulated | All modelled | Yes (order) | No (adapter-owned) | n/a |
| Chargebee sim | simulated | None | Yes (per-operation artifacts, C1) | No (adapter-owned) | n/a |
| Chargebee-live | simulated + live reads only | None | Yes (post-commit reads) | Yes, FULL_ITEM_SET | **Never executed; not authorized** |

Chargebee-live additionally carries the **preservation blocker** (§5): OPERATION-authorized
update commits refuse pre-dispatch on that adapter alone (FULL_REPLACEMENT_ONLY), which is
also why the research harnesses that attempt such commits fail behind the guard (gap G-20).

The honest headline: v0.6.2's normative machinery is implemented once, in the shared
core/store, and exercised against five adapter models of very different shapes — which is
exactly what a reference implementation is for. It is not evidence that any real provider
conforms, that any provider has adopted SCQ, or that a live commit against any provider
would behave as the models do.
