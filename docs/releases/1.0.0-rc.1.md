# @agorail-labs/scq-reference 1.0.0-rc.1 — release candidate notes

**Status: CANDIDATE — prepared for independent review. Not a
stable release; the current published line remains
`0.6.2-experimental.1`, and the specification remains SCQ v0.6.2.**

## What this candidate is

The first release candidate for SCQ's stable core: quote →
acceptance-envelope → durable commit → receipt/replay →
reconciliation for quantity, plan, cadence, and cancellation
changes, under the proposed 1.0 contract in
`docs/STABLE-RELEASE-READINESS.md` and `docs/VERSIONING-POLICY.md`.

## Changes from 0.6.2-experimental.1

- No export-name changes (machine-verified identical surface:
  22 values, 69 types).
- Envelope naming: `maxImmediateNetDecrease` is canonical;
  `maxImmediateCreditDecrease` remains a deprecated alias with
  identical semantics; both spellings in one envelope are refused
  as ambiguous (Issue #64, closed).
- Durable store schema v5: append-only verified recovery (Issue
  #51) and namespaced dispatch exclusion (Issue #45).
- `better-sqlite3` ^11 → ^13: restores the durable store on
  Node 26 (the ^11 line cannot build there). `engines: node >=22`;
  validated on Node 22/24/26.
- Documentation: API reference, versioning policy, migration
  guide, support matrix, idempotency/reconciliation guide,
  recovery runbook, security audit.

## Known limitations

- The core trusts adapter-established classification (G-01).
- No live provider dispatch; no exactly-once provider execution
  or cross-provider atomicity is claimed.
- The local-pack checksum discrepancy remains unexplained; this
  candidate must be produced through the CI release workflow,
  whose recorded hashes are the artifact of record.
- Independent review is a pending gate — see
  `docs/RELEASE-QUALIFICATION.md`.
